# Industrial Communications & OT Toolkit
## Project Specification

## 1. Project Overview

The **Industrial Communications & OT Toolkit** is a lightweight offline desktop application for automation, controls, commissioning, maintenance, and OT engineers.

The application provides three primary capabilities:

1. **Industrial communication reference**
2. **Practical engineering calculators and diagnostic tools**
3. **Technology hierarchy and comparison**

The application is designed to clarify the relationship between physical communication standards, network technologies, industrial protocols, application protocols, and higher-level profiles.

It is not intended to replace protocol analyzers, PLC engineering software, network scanners, or vendor-specific diagnostic tools.

The core product principle is:

> Help an automation engineer quickly understand, calculate, compare, and troubleshoot common industrial communication technologies from one offline application.

---

## 2. Primary Goals

The application should allow an engineer to:

- Understand what a communication technology actually is.
- Determine where it fits in the industrial communication hierarchy.
- Understand what lower-layer technology it uses.
- Identify related technologies and protocols.
- Compare similar industrial communication technologies.
- Perform common Modbus calculations.
- Decode PLC and Modbus data.
- Perform basic Ethernet and subnet calculations.
- Look up common OT ports.
- Generate basic network diagnostic commands.
- Access short protocol troubleshooting guides.
- Search industrial communication terminology quickly.
- Use the entire application without an internet connection.

---

## 3. Non-Goals

Version 1 will NOT provide:

- Live PLC communication

- Network scanning
- Automatic device discovery

## 35. Troubleshooting Quick Guides

Every major communication technology should include a short troubleshooting checklist.

The standard troubleshooting order should generally follow:

```text
Physical
  ↓
Link
  ↓
Addressing
  ↓
Network
  ↓
Protocol configuration
  ↓
Application
```

### PROFINET

1. Check cable and link LEDs.
2. Check device name.
3. Verify IP configuration.
4. Check duplicate addresses or names.
5. Verify GSDML and hardware configuration.
6. Check PLC diagnostics.
7. Check switch/VLAN configuration.

### EtherNet/IP

1. Verify Ethernet link.
2. Verify IP/subnet.
3. Test basic connectivity.
4. Verify ports.
5. Verify EDS/device configuration.
6. Check electronic keying.
7. Check RPI.
8. Check multicast or I/O connection faults.

### Modbus RTU

1. Verify wiring.
2. Verify A/B polarity.
3. Check termination.
4. Check baud rate.
5. Check parity.
6. Check stop bits.
7. Verify device address.
8. Verify register offset.
9. Verify function code.
10. Verify byte/word order.

### IO-Link

1. Verify device power.
2. Verify master port configuration.
3. Verify cable/wiring.
4. Check device detection.
5. Verify IODD/configuration.
6. Check process-data mapping.
7. Review IO-Link master diagnostics.

### AS-i

1. Verify AS-i power supply.
2. Check master diagnostics.
3. Verify slave address.
4. Check duplicate address.
5. Inspect cable connections.
6. Measure network voltage.
7. Verify configured slave profile.

## 52. Product Definition

The finished V1 should be described as:

> **Industrial Communications & OT Toolkit is an offline desktop field companion that helps automation and OT engineers understand communication technologies, visualize how protocols and standards fit together, perform common network and Modbus calculations, compare technologies, and troubleshoot industrial communication systems.**

The key differentiator is not merely providing protocol definitions.

The application should answer:

> **“What is this technology, where does it fit, what does it run on, how is it related to the other technologies I use, and what should I check when it fails?”**

That should remain the guiding principle for the entire project.
